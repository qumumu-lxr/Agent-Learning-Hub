# Agent Shipping Notes

A real agent project needs a clear user, a narrow task, and measurable success criteria.

Evaluation protects the project from demo bias. A useful eval set includes tasks, expected results, actual results, failure categories, traces, latency, and cost.

Observability makes failures diagnosable. A trace should show planned actions, tool calls, observations, retries, and final answers.

Permission boundaries matter because agents can call tools. File writes, browser submissions, payment, publishing, and external messages should require explicit approval.

An agent harness improves reliability by managing tools, state, permissions, logs, retries, timeouts, memory, and context limits.
